YAC source setup for Linux and macOS
==================================

This setup is for initial testing on Linux and macOS. Radio discovery,
keyboard input and speech/braille access still need checking on these
systems. The Windows YAC.exe package cannot run natively on either system.

Linux includes ordinary x64 computers and Raspberry Pi systems. The same
source setup applies to both: use Python installed for that machine's OS
and architecture. On a Mac, use Terminal with Python for that Mac.

KEY BINDINGS

Keep KEY-BINDINGS-English.txt open in a separate window while using YAC.
German: TASTENBELEGUNG-Deutsch.txt; Polish: SKROTY-KLAWISZOWE-Polski.txt;
Spanish: TECLAS-Espanol.txt. These short charts list implemented commands
and submenu sequences. The installer copies them beside the program.

INSTALLING

1. Download and extract the YAC source ZIP. Keep its files together.
2. Open a terminal and change to the extracted source directory.
3. Run:

       sh install-yac.sh

   You do not need to mark the script executable when running it this way.
   Run it as your normal user, without sudo.

The script checks for python3 and reports its version. YAC requires Python
3.10 or newer. If Python is missing or too old, the script advises using
your package manager's installation instructions and exits. On macOS,
Python is also available from https://www.python.org/downloads/macos/.
The script does not install or replace system Python.

The installer detects the operating system: macOS uses ~/Applications/yac;
Linux uses ~/.local/yac. The Linux paths below become ~/Applications/yac
on macOS. Older ~/yac installations are left unchanged; this does not
automatically migrate them.

It asks before creating or updating the selected directory. It copies new or changed YAC
source and data files, leaving identical files untouched. Updates preserve
your yac.ini (including language and name), logs, other personal files and
the private environment in ~/.local/yac/.venv. It creates that environment if missing.
On updates, compatible pyserial is reused without running pip; otherwise pip
installs it and requires internet access. Setup does not start YAC or open
serial ports. An existing yac command is left unchanged.

For first-run language/name testing, back up yac.ini and clear only its lang
and call values while YAC is closed. You do not need to delete ~/.local/yac or .venv.

Some Linux distributions provide venv/pip support in a separate package.
On Debian, Ubuntu and Raspberry Pi OS this is usually python3-venv.
Consult the instructions for your distribution. If environment creation
or dependency installation fails, the script prints recovery commands.
Files already created remain available; they are not deleted automatically.

Once installed, the script creates ~/.local/yac/run-yac. It separately offers to
create /usr/local/bin/yac if that directory exists. If administrator
permission is required, it explains this before asking and uses sudo only
to install the launcher. You may be asked for your login password; the
terminal usually does not echo password characters.

If the system shortcut is unavailable or declined, it offers a personal
shortcut at ~/.local/bin/yac. It does not change your shell configuration
or overwrite an existing yac command. The system shortcut points to your
personal installation; it is not a shared installation for other users.

RUNNING YAC

Open a terminal and run:

    ~/.local/yac/run-yac

If the optional shortcut's directory is in your PATH, you can instead run:

    yac

The launcher uses the private Python environment directly. You do not need
to activate it first. Settings and logs remain inside ~/.local/yac regardless of
the directory from which you start the launcher.

Follow the language and name/callsign prompts. Close any other program
using your radio's port before starting YAC. YAC attempts to discover the
radio. Screen-reader speech and braille come from your screen reader's
access to the terminal; the script does not configure the screen reader.
Press h at the top level for the command list, and q to quit.

BRAILLE SETUP NOTES

See BRAILLE-FS-START-HERE.txt in the extracted source package for USB
commands using Freedom Scientific (fs) and HumanWare Brailliant BI 40X
(hw), with the North American computer braille text table en-nabcc.
Freedom Scientific braille output on Linux has now received a positive
user report. HumanWare remains to be tested in this setup. The reported
Apple / macOS output issue remains unresolved; loading a driver or table
alone does not establish that the expected output is working.

IDLE RADIO CONNECTIONS

YAC quietly reads frequency every five seconds while waiting for command
keys, including mode, band, settings and offset menus. Queries and user
commands run in the same thread, so their replies cannot overlap. Polling
pauses during editable fields and command execution; it does not require
keypresses during ordinary listening. Successful checks produce no speech
or braille output. The simulated radio is not polled.

Three consecutive failed checks produce a localized connection-lost
message, kept under the terminal cursor. YAC then retries the original
USB identity (if available), or the original port, and verifies the model
at its existing baud rate and CI-V address. It does not scan for an
alternative radio, switch to simulated mode, or restore radio settings.
Radio commands are blocked once loss is detected; h and q remain available
at the top level. Successful recovery produces a connection-restored
message. A device without a USB serial identity must return on its original
port; that fallback cannot distinguish two units of the same model.

These checks are not an operating-system sleep inhibitor. They do not
guarantee that macOS keeps USB active on battery or during sleep. Mac
sleep/wake and real-device reconnection still require hardware testing.

RADIO ACCESS ON LINUX

USB serial device names commonly include /dev/ttyUSB0 or /dev/ttyACM0.
If YAC finds a port but cannot open it, inspect the device's ownership and
your user's groups. For example:

    ls -l /dev/ttyUSB0
    id

Use the actual device reported by YAC. Your distribution may require your
user to belong to a serial-access group, often dialout on Debian-based
systems. Follow the distribution's instructions and sign out and back in
after a group change. The installer does not change group memberships or
device permissions. Run YAC as your normal user.

RADIO ACCESS ON MACOS

YAC looks for the Mac's serial devices, commonly /dev/cu.*. Some radio
interfaces need the manufacturer's macOS USB driver. Use the driver for
your interface and macOS version. Installing YAC does not install drivers.
Terminal access through VoiceOver and a braille display needs practical
testing; compatibility is not yet established by this source setup.

MANUAL SETUP ALTERNATIVE

From an extracted source directory with Python 3.10 or newer available:

    python3 -m venv .venv
    .venv/bin/python -m pip install "pyserial>=3.5,<4"
    .venv/bin/python yac.py

Keep modules, lang and rad_cmds beside yac.py. This approach keeps YAC in
the extracted directory rather than copying it to ~/.local/yac. Settings and logs
will be stored beside that copy of yac.py.

UPDATING YAC (NEXT RELEASE)

After installing a package with the updater, type update-yac in your terminal.
It checks published GitHub releases, including betas, without requiring Git.
It says YAC is up to date when the installed release matches. Otherwise:

A new YAC update is available. r read changes; q cancel; Space install.

r reads the release notes and returns to the prompt. q cancels. Space downloads,
checks the SHA-256 checksum, extracts source and runs the installer. It does not
ask a second time. The installed changelog.txt contains the shipped changes.
The updater uses Python's ZIP support; unzip is not required.

Close YAC first. Running YAC and updating share a lock on Linux/macOS, preventing
simultaneous use. A failed installer restores the previous program files while
leaving yac.ini, logs and the private environment alone. Keep error messages if
setup fails. The checksum verifies consistency with the published release; it
is not an independent signature.

Initial setup separately offers /usr/local/bin/update-yac and may ask for sudo
only to create that shortcut. The shortcut points to your personal installation.
An existing command is left unchanged. If the shortcut is declined, run the
update-yac script inside your installation folder. Do not run updates with sudo.

Next releases use yac-source.zip with a dated folder inside. The updater also
recognises the older dated YAC-source ZIP names. Existing installations without
release metadata will be offered the newest published release once. Pre-updater
versions must be updated manually first. Until a package containing this updater
is released, existing public downloads do not provide this command.

Installer prompts

Enter accepts Yes at Install YAC?, Create YAC launcher? and Create update
launcher?. Answer n to skip. Existing launchers are preserved silently.
YAC uses its own private Python environment; other environments are unchanged.
If no launcher is created or its directory is outside PATH, the installer
prints the full launch path. The Pi installer finishes with yac-pi.
