YAC platform setup and tester packaging
=======================================

BUILD FOLDERS

Current ZIPs and checksums are in the project root. previous-builds/<date>
preserves earlier releases, with numbered subfolders for repeat builds on
one date. builds/runnable holds the runnable Windows folder; builds/.work
holds temporary build output.

Packaging validates staged files before publishing. A new date, or a filename
that would replace an existing release artifact, archives the current release
first. Source and Windows packages from the same date can share the root.
Only recorded release artifacts are archived; project files stay in place.
Generated packages and previous-builds are excluded from Git.

WINDOWS DEMO

From the project root, with Python and the build dependencies available:

    py -3 build_demo.py --date YYYY-MM-DD

The script expects PyInstaller and pyserial in .build-deps. It stages the demo,
copies the public key charts and first-steps guides, validates the complete
package, and publishes the ZIP, checksum and runnable folder together.
Distribute the ZIP or the complete runnable folder, never the executable alone.
A failed validation leaves the previous release in place.

PORTABLE SOURCE

    py -3 package_source.py --date YYYY-MM-DD

This validates and publishes a source ZIP and SHA-256 checksum to the project root.
It includes all four public key charts and the Linux/macOS setup instructions.
Use the release date in place of YYYY-MM-DD, or omit --date for today's date.

TESTS

    python -m unittest discover -s tests -t .

Offline tests live in tests. Manual checks live in tests/hardware and run as
modules from the project root, for example:

    python -m tests.hardware.radio_read_check

Inspect hardware scripts before running them; some change radio settings.
The folder reorganization does not build or publish a new release by itself.

Linux (x64 computers and Raspberry Pi)
------------------------------------

The same source setup applies to x64 Linux computers and Raspberry Pi.
An interactive setup script is now available: from the extracted source
folder, run sh install-yac.sh. See doc/linux-macos-setup.txt for the full
installation, launcher and radio-access instructions.

YAC requires Python 3.10 or newer. Check whether Python 3 is present:

    python3 --version

If it is, create an isolated environment in the YAC directory and install
pyserial there:

    python3 -m venv .venv
    source .venv/bin/activate
    python -m pip install --upgrade pip
    python -m pip install pyserial
    python yac.py

If creating the environment reports that venv support is missing, install the
matching distribution package for the Pi's OS (on Raspberry Pi OS/Debian this
is commonly python3-venv), then repeat the commands. A system package such as
python3-serial is another option, but the virtual environment keeps YAC's
Python dependencies separate from operating-system Python packages.

Linux may restrict access to serial ports. If YAC can see a port but cannot
open it, check the port's group and the user's permissions; on many Debian
systems the serial-access group is dialout. After changing group membership,
sign out and back in before testing again. The exact port name and any USB
adapter driver depend on the Pi, operating system, and radio interface.

macOS
-----

The same interactive script can be used from Terminal: sh install-yac.sh.
Mac radio, terminal and accessibility testing is still required.

Use the same virtual-environment approach, with the Python 3.10+ installation
available on the Mac:

    python3 --version
    python3 -m venv .venv
    source .venv/bin/activate
    python -m pip install --upgrade pip
    python -m pip install pyserial
    python yac.py

Serial device names and USB adapter drivers differ from Windows and Linux.
Check the device names YAC reports and install the adapter manufacturer's
macOS driver if required. A packaged macOS app would need its own Mac build and
verification; signing/notarization may be needed for a polished public
distribution.
