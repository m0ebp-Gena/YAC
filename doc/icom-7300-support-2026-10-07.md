# IC-7300 and IC-7300MK2 support

Implemented 7 October 2026. Hardware verification is pending for both models.

## Official Icom references

- Original IC-7300: https://www.icomjapan.com/support/manual/2271/
  Local reference: pdfs/IC-7300_ENG_FM_12b.pdf.
  Section 19, especially 19-2 through 19-8 (commands), 19-9 (frequency/mode)
  and 19-13 (RIT and selected/unselected VFO formats).
  Receiver limits: section 16, PDF page 150.
- IC-7300MK2: https://www.icomjapan.com/support/manual/4486/
  Local reference: pdfs/IC-7300MK2_ENG_CI-V_0.pdf.
  Command table and format pages 16 and 23, plus the official product
  specifications: https://www.icomjapan.com/lineup/products/IC-7300MK2/.

Keep the reference PDFs for local development; the demo packaging includes
rad_cmds, not the manuals or extracted text.

## Implemented behavior

Model definitions live in rad_cmds/icom/CI-V/models/ic-7300 and ic-7300mk2.
profile.json supplies receiver limits, modes, band destinations and the list
of command files. Hexadecimal files contain command/subcommand bytes only;
YAC supplies the connected radio's address, frame delimiters and data.
The IC-705 now uses this same definition mechanism.

- e enters frequency in MHz, with exact readback and rollback on failure.
- Comma/full stop tune by the configured mode-specific increment.
- s then s saves that increment in hertz, using the existing settings flow.
- b navigates HF, 6 m and 4 m. Returning to a band recalls its frequency,
  mode and filter during the session. Failed changes attempt restoration.
- m offers the modes in the corresponding model profile.
- z rounds to the nearest kilohertz and restores RIT/Delta-TX enable states.
- o adjusts receive/transmit offsets in 10 Hz increments or clears them.
- s then v selects VFO A on the first request, then alternates B/A.
  Acknowledged selection is followed by frequency/mode readback. Band
  memories are kept separately for each YAC-selected VFO.
- w/f show signal strength, frequency and mode. The S-meter curve is an
  approximation using the existing Icom calibration, not hardware calibration.

Additional selected/unselected VFO, split and hardware tuning-step command
files are recorded for future controls. Those files do not add extra keys.
YAC's tuning increments are software settings, separate from the hardware
10 command. CTCSS/DCS remains unchanged and is not enabled for these models.

Discovery recognizes both model IDs and includes the MK2 factory address.
A reply to the identification query takes precedence over a USB description,
including when the user has changed the radio's CI-V address.

CI-V reads/writes wait for the addressed radio's reply rather than stopping
at a local echo. Frequency readback must match exactly for supported Icoms.

## Radio choice correction

When several radios are listed, no radio is preselected. Enter a number,
then Space to accept; q cancels. Space before a number does not select the
first radio. The chosen number/model is echoed without claiming that a
selection has already been confirmed.

## Validation

Run:

    python -m unittest tests.test_radio_responses tests.test_icom_7300 -v

The added tests drive the actual CI-V encoders/decoders through a simulated
serial device with fragmented replies and local echoes. They cover frequency
limits, exact readback, rejected commands, rollback, modes, tuning increments,
band recall, rounding, offsets, VFO selection, discovery at a changed address,
the keyboard loop and waiting for a user's radio choice.

Result: all 27 regression tests passed, including 15 added integration and
selection checks. No physical radios were used and no serial ports opened.

The already distributed YAC-2026-10-07.zip has not been replaced. These are
source changes for the next build; the published executable is unchanged.
